01 / 가볍게 시작3분

설명해주는 것과 만들어주는 것.

“체크리스트를 만드는 법”을 듣는 것과 “직접 클릭할 체크리스트”를 받는 것은 다릅니다. 오늘은 AI에게 여러 단계를 맡길 때 무엇을 정해줘야 하는지 알아봐요.

오늘의 준비

A와 B 중 하나만 골라요. A는 진행자가 준비한 Codex 환경에서 작은 도구 만들기, B는 지금 쓰는 AI 앱에서 여러 단계의 계획 맡기기예요. 두 실습을 모두 할 필요는 없습니다.

A를 고른다면 진행자가 미리 별도 빈 폴더를 만들어 열어주세요. 설치·로그인·권한 설정은 수업 전에 끝내고, 준비가 안 됐다면 B로 바로 진행합니다.

02 / 원리 알아보기7분

모델, 도구, 에이전트의 역할.

1. 모델은 판단하고, 도구는 작업을 수행해요.

모델은 요청을 해석하고 다음 행동을 결정할 수 있어요. 검색 도구는 웹 정보를 찾고, 계산 도구는 계산하고, 파일 도구는 파일을 읽거나 바꿉니다.

모델이 “저장했어요”라고 말하는 것만으로 실제 파일이 생기는 것은 아니에요. 어떤 도구로 무엇을 했고 결과물이 어디에 있는지 확인해야 합니다.

2. 에이전트는 결과를 보며 다음 단계를 이어가요.

목표를 받고 계획하고, 도구를 사용하고, 결과를 살펴 다음 행동을 이어가는 방식을 에이전트라고 부릅니다. 한 번에 모든 결과가 맞는다는 뜻은 아니에요.

오래 작업했다고 잘된 것도 아니고, 자율적으로 움직인다고 무제한 권한을 줄 필요도 없어요. 작은 범위와 확인 가능한 완료 기준이 출발점입니다.

3. 요청의 범위와 실제 권한을 함께 봐요.

“이 폴더에 파일 하나만 만들어줘”는 작업 범위에 대한 지시예요. 앱의 폴더 접근·네트워크·실행 권한은 별도로 적용됩니다. 부탁 문장만으로 기술적인 접근 제한이 생기지는 않습니다.

초안 작성과 실제 발송, 파일 만들기와 외부 공개는 다른 행동이에요. 이번 실습은 개인 맥북에서 확인할 작은 결과물로 범위를 정합니다.

03 / 같이 해보기15분

A 또는 B, 하나만 골라서 15분.

A는 직접 작동하는 도구를 만드는 체험입니다. B는 작업을 나누어 맡기는 연습이며, 실제 파일 실행을 체험하는 것은 아니에요.

복사 버튼은 문장만 복사해요. 사용 중인 AI 대화창에 직접 붙여 넣어 보내주세요.

1. 경로와 완료 기준 고르기 · 3분

A: 진행자가 열어둔 빈 연습 폴더를 확인하세요. 만들 것은 체크 표시와 초기화 버튼이 있는 아주 작은 외출 도구입니다.

B: 일반 대화창에서 “주말 한 시간 취미 시간”을 준비합니다. 결과는 계획 두 개를 비교한 뒤 고른 한 개의 실행 목록이에요.

어느 쪽이든 끝났다고 판단할 기준을 먼저 읽어봅니다. A는 파일이 열리고 체크·초기화가 동작하기, B는 준비·실행·정리가 한 시간 안에 들어가고 바로 할 첫 행동이 있기예요.

2. 선택한 작업 부탁하기 · 6분

A를 고른 경우 아래 요청을 Codex에 보내세요. 코드를 직접 이해하거나 작성할 필요는 없지만, 화면이 원하는 대로 작동하는지는 직접 봐요.

지금 선택한 빈 연습 폴더에 outing-checklist.html 파일 하나를 만들어줘.
브라우저에서 더블클릭으로 열어 쓸 외출 체크리스트야.
항목은 열쇠, 휴대폰, 지갑, 날씨 확인 네 개로 시작해줘.
각 항목을 체크할 수 있고 “체크 초기화” 버튼을 넣어줘.
새로고침하면 체크는 초기화되어도 돼.
외부 서비스 연결, 패키지 설치, 인터넷 배포, 다른 폴더 수정은 하지 마.
완료하면 파일 위치와 실제 확인한 동작, 확인하지 못한 부분을 알려줘.
이렇게 해도 좋아요
  • B를 골랐다면 다음 문장을 대신 보내세요: “집에서 한 시간 취미 시간을 보내고 싶어. 새 물건은 사지 않을 거야. 먼저 내 취향을 질문 두 개로 확인하고, 활동 두 개를 비교해줘. 내가 고르기 전에는 세부 계획을 확정하지 마. 고른 뒤에는 준비·실행·정리가 한 시간 안에 들어가는 체크리스트를 만들어줘.”
  • 권한 요청이 뜨면 무엇을 읽거나 바꾸려는지 함께 읽으세요. 요청 범위를 넘는 설치나 외부 접근이 필요해 보이면 중단하고 더 단순한 방식으로 요청합니다.

3. 완료했다는 말 대신 결과 보기 · 4분

A: Finder에서 생성된 HTML을 직접 열고 한 항목을 체크한 뒤 초기화 버튼을 눌러보세요. 체크가 풀리는지, 새로고침 시 안내한 대로 동작하는지 확인합니다.

B: 고른 활동의 준비·실행·정리 시간을 합쳐보세요. 집에 없는 준비물을 가정하거나 취향 질문에 답하기 전에 계획을 확정하지 않았는지 봅니다.

안 되는 부분이 있으면 관찰한 현상을 그대로 말해주세요. 원인을 추측할 필요는 없어요.

확인해보니 [실제로 관찰한 문제]가 있어.
원하는 동작은 [내가 원하는 결과]야.
이 부분만 고치고, 잘 작동하던 나머지는 유지해줘.
확인하지 못한 동작은 확인했다고 쓰지 말아줘.

4. 작업 범위와 결과 한 번 더 보기 · 2분

A: 연습 폴더 안에 의도한 파일만 있는지 확인해요. 이번에는 자동 저장, 로그인, 공유 기능을 추가하지 않아도 충분합니다.

B: 지금 바로 시작할 첫 행동 하나가 분명한지 보세요. 여러 단계의 부탁을 통제하는 연습을 마친 것입니다.

이번 요청에서 만든 결과, 실제로 확인한 것, 아직 확인하지 못한 것을 각각 짧게 정리해줘.
새 기능을 추가하거나 외부에 공개하지 말고 여기서 마무리해줘.
진행자 메모 · 실습을 도와줄 때
  • A를 선택했다면 공식 시작 안내에 따라 미리 환경을 준비하세요. 실제 화면과 기능은 계정·버전에 따라 달라질 수 있어요. CLI나 Git은 이번 체험의 학습 목표가 아닙니다.
  • 선택한 폴더가 보안 경계 전부는 아니에요. 앱의 실제 권한 설정도 확인하고, 작업용 빈 폴더를 사용하세요.
  • A가 막히면 B로 전환하세요. 개발 오류를 길게 해결하는 것보다 목표·범위·검토라는 개념을 익히는 편이 중요합니다.
  • 잘 작동한다면 기능을 계속 늘리기보다 여기서 끝내보세요. 완료 기준을 충족하면 멈추는 경험도 필요합니다.

함께 이야기하기: 체크리스트를 만들다가 외부 공개를 제안한다면?
